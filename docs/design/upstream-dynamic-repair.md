# 上游动态修复：从具体反例到可冻结的规则

本文记录 OCR 初级结果和确定性分析的改进经验。目标不是让评分更漂亮，而是让无需
LLM 的页真正变好：内容完整、来源可追踪、段落关系正确，并保持增量交付。

这里的“动态修复”指用真实失败持续指导算法迭代，不是运行时自动改提示、在线调阈值，
也不是针对每本书保存补丁。最终进入运行时的是通用、确定性、有反例约束的规则。
JEV 的职责和证据标准见 [JEV 结构审核](jev-structural-review.md)，具体结果与验证
范围见[自动分析验证](../verification/jev-upstream-automatic-analysis.md)。

## 先分清是谁出了错

送修比例高有两种不同原因：上游确实制造了很多结构错误，或审核器把正常结果判错。
只看送修比例，无法区分两者。调高阈值虽然能降低调用量，却不能证明内容改善。

本轮先明确审核对象：只看当前页可修复的结构关系，最多使用相邻三页的初级证据；
不审作者措辞、错别字或最终目录层级。人工判断也不能用模型没有的远处内容来定罪。
审核器相对稳定后，将提问、模型、服务和工作点固定，再主攻上游，避免两边同时移动。

冻结的局部 JEV 是隔离研究协议，尚未替换包内审核实现，不能把实验工作点误称为
生产默认值。它是主要观察工具，也保留已知盲点；来源守恒、几何反例和人工检查仍
独立生效，不能只因它放行就宣布正确。

## 用一个失败发现共因，再回到整体

有效的反馈循环从一处可解释的接缝开始：当前两个框为何被合并或拆开？决定发生在
OCR 分类、阅读组、自然段续接，还是后续来源投影？先定位负责这个决定的模块，
不要直接向提示词添加“不要犯这个错误”。

竖排调查就是一个例子：OCR 列框彼此贴边，阅读分组没有形成波谷；Jointer 在组间
检查续接，却把组内各框当作独立段落。问题在“阅读组不等于自然段”，不是模型没有
理解词义。修复应让真实列边界经过已有续接检查，保留原有 OCR 顺序，而不是另写
一套全页排序或绕过来源关系。

小范围实验负责快速证伪，完整样本负责检查偏移。先固定一个失败及其最近的反例，
做隔离变更；确认有效后，再回到所有开发页、补充文档和重复评分。只修好被盯住的一页，
不代表规则能采用。不能把书中原句、人物或页码放进生产提示或条件判断，这会泄题。

## 每个新规则都要有反面

第一版竖排续接修好了断词，却错误合并了编号条目。因此不能只数修好的例子，必须
追查每个新的结构变化，再补上通用的编号语法和上下文约束。

对应关系必须明确：

| 正向证据 | 必须保护的反例 |
| --- | --- |
| 贴边平行竖排列框可能属于同一自然段 | 密集横排窄栏、标题、独立编号条目 |
| 引号中的数字可能是校释编号 | 普通叙述中的数字术语 |
| 明确的首行缩进可能证明新段落 | 多行整框、未完词、同一行上的归属语 |
| 像素投影可能证明一个框内有多个竖排列 | 对齐字格、连续线条、空白和不明确方向 |
| 严格纯白输入无需 OCR | 一像素的浅色墨迹、非不透明图像、旧有效缓存 |

反例不是为了给实现补无穷多特判，而是限定证据能说明什么。若正反例无法区分，应
返回未知、沿用原规则或交给下游审核，不要强行给出一个貌似确定的判断。

## 优先补可测量的证据

多行 bbox 的左边界不能代表首行起点。继续从整框猜缩进，只会制造更多例外。
改为直接观察当前图像的墨迹行带，测量首行相对后续完整行的左缩进；多条后续行
需要形成多数一致的基线。只有两行时可以测量，只有一行时不能凭空构造基线。

同样，文字密度只能保守估计竖排。一个 OCR 框包含多列时，面积估计可能拒绝真实
竖排；列间留白和纵向墨迹可以提供补充正证据。它们仍需文字类型、CJK 比例和相邻
几何共同成立，不意味着所有高窄框都是竖排。

观测与决定分开：raw OCR XML 保存可选证据，段落模块决定如何采用。未知值保持未知，
旧缓存缺字段时继续原有路径。不能改写旧 OCR 文字来“修复”评分，也不为使用新证据
强制重跑全书。实际需要重新生成证据时，使用独立目录，保留旧缓存和哈希。

像素工作还要有资源边界：在裁剪前限制面积，受到资产遮挡时不推断，不保留全书
图像，不增加模型请求。只使用当前页已有图像，不引入全书屏障。新增计算不能让
`on_body`、`on_footnote` 等内容交付退化为末尾集中输出。

## 避免制造错误，比事后修复更可靠

客户文档的三个严格空白页面被 OCR 生成为整页数字公式。凭“数字占满一页”删除内容
很危险，书里可能真有这样的页面；重新渲染原图，确认所有像素严格纯白，才有直接
证据跳过模型调用。

同一个原则也适用于脚注二轮扫描：擦除后若严格纯白，保留第一轮正文与资源消耗，
不再请求一次可能产生幻觉的 OCR。不是模拟一次成功请求，也不伪造 token 或观察事件；
实际没调用就没有请求消耗，页面自身仍正常落盘和完成。

这一变更必须覆盖全空输入、混合输入和两条 vendor 调度路径，不能只测判断函数。
旧测试若用白纸模拟“有内容并应请求 OCR”，应给 fixture 加真实墨迹，继续验证原本
的并发、重试和 usage 行为，而不是禁用空白检测来维持测试。

## 配对结果比漂亮总数重要

比较上游版本时固定原始 OCR、JEV 协议、实际服务和工作点。完整请求哈希相同可以
复用对应轮次的响应；输入变化才重新请求。必须说明复用了多少，不能把缓存响应
包装成多轮全新调用，也不能跨服务配置混用结果。

每轮先看来源身份、文字、框及顺序有没有丢失，再看改变的决定。少送一页，可能是
错误被修好，也可能只是把应审核的内容删掉；必须能解释是哪一种。页面仍因其他
问题送修，也不代表本次改动没有改善其中一个接缝。

给读者的主指标保持简单：JEV 判对多少页、判错多少页，各占多少。假阴性和假阳性
只有完成相应人工核验后才报告；选定正常子集没有误送，不等于完整真实误报率为零。
百页开发集和客户补充集分开列，不能混成网站流量分布。修复后的旧标签也不能直接
继续当作错误，或未经重审就改成正常。

本轮百页三次配对的判错从 48、49、49 页降到 21、22、22 页；补充三十二页从
4 页降到 1 页。它们说明这批通用改动值得保留，不构成网站整体精修比例保证。
完整假阳性、假阴性仍未核验。详细中间版本和实际验证边界以验证报告为准。

## 何时停止，下一轮做什么

当通用证据的收益变小，而剩余问题需要越来越强的角色假设或针对样本的规则时，
应冻结成果，而不是把每个剩余判错都编码成例外。

图注就是这次的边界：图片下的说明和署名可能被接入正文，但直接在所有图片处断段，
会破坏穿过插图继续的正文；直接搬进现有 caption，又可能丢失独立文字框的来源。
这是角色与来源表达的问题，不应通过删文字或改段落表面形态掩盖。

正文后的 ASCII 数字也可能是脚注号、普通编号或小数的一部分。没有进一步证据时，
不能为了露出句号而统一剥掉它。装饰符和无编号脚注同样不能用一种删除规则处理。

当前收敛只限于这批样本和已验证的通用几何方法，不是所有 PDF 问题都已解决。
下一步应先在未参与调优的新书上验证，并按相同证据边界核验误送和漏送；之后再
单独改善角色识别或来源模型。这样可以保住已取得的收益，也避免继续迎合开发集。
