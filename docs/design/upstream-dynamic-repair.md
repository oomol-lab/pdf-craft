# 上游动态修复的设计原则

上游修复的目标是减少 OCR 初级结果和确定性分析造成的结构错误，同时保持内容
完整、来源可追踪和增量交付。这里的“动态修复”指由真实失败指导通用规则改进；
运行时不针对书籍保存补丁，不自动改提示或在线调阈值。

## 固定审核标准，修复错误来源

送修多可能因为上游错误多，也可能因为审核误判多。两者必须分开核验。改变阈值
只能改变调用量，不能证明内容变好。比较上游版本时，原始 OCR、JEV 协议、模型、
服务和工作点应保持一致。

修复应落在制造错误的模块。OCR 框、阅读组和自然段是不同概念：同一阅读组中的
竖排列框也需要经过续接判断，不能直接当作多个独立段落。相应修复应复用段落
连接契约，保留原有来源顺序，不另建一套全页排序。

少送一页不等于修好一页。验收必须先确认来源身份、原文、框和顺序没有丢失，再
检查结构决定。不能通过删除应审核的内容、改写标签或降低审核标准来获得改善。

## 测量证据与结构决定分离

像素观测提供局部证据，段落模块决定如何采用。原始 OCR XML 保存可选观测，旧
缓存缺字段时继续既有路径；未知值保持未知，不为新规则静默改写有效缓存。

多行 bbox 不能证明首行缩进。首行缩进来自实际墨迹行带相对后续完整行的测量，
多条后续行需要形成多数一致的基线。单行几何、句尾标记和缩进必须联合使用，
不能凭一个句号或一个窄框强制断段。

竖排方向也不能只由高窄外形决定。文字密度、CJK 比例、平行框及列间墨迹留白提供
互补证据；无法区分的字格保持未知。检测到竖排列边界，只说明需要检查续接，
不意味着所有相邻列必须合并。

| 可采用的证据 | 必须保留的约束 |
| --- | --- |
| 平行竖排列框 | 标题和独立编号条目仍可另起 |
| 引号包围的数字编号 | 需要已有编号条目上下文，不切断普通数字术语 |
| 明确首行缩进 | 不切断未完词，不从多行整框猜测 |
| 多列竖排墨迹 | 不将横排窄栏或对齐字格强判为竖排 |
| 严格纯白输入 | 浅色墨迹和不明确的透明度仍走 OCR |

测试需要覆盖这些机制的正反两面，并通过真实 decoder、缓存往返和两种脚注投影
验证接线。不能只在 helper 上通过，也不能写入书籍原句或页码作为判断条件。

## 有直接证据时避免无效模型调用

严格纯白的渲染结果无需 OCR。判断依据是像素，而不是“内容像数字”或“文字很少”；
即使只有一个近白墨点，也继续原有识别路径。

本地和 vendor 首轮均可保存空页和几何并正常完成。vendor 脚注二轮擦除图严格纯白
时，保留第一轮正文与 usage，跳过第二次请求。未发出的请求不产生观察事件或 token，
不能模拟一次成功调用。全空输入、混合输入及两条 vendor 调度路径遵守相同契约。

渲染和图片大小保护仍先于这些观测。像素裁剪在分配前限制面积，证据被资产遮挡
时不推断，不保留全书图像，也不增加全书等待。新规则不得让 `on_body` 和
`on_footnote` 退化为文件完成后的集中通知。

## 验证结论的边界

小范围反例用于验证错误机制，完整样本用于发现规则对其他内容的影响。未经整体
核对的局部改善不能视为可采用的通用规则。完整请求相同且协议、服务一致时，可以
复用对应响应，但必须与全新请求区分；重复开发页也不等于独立书籍验证。

结果报告使用页数和明确分母，分别列出 JEV 判对和判错；假阴性和假阳性需要人工
核验。已修复旧错误的标签需要重新判断，已知正常子集没有误送不能代替完整误报率。
最终结果与验证覆盖见[自动分析验证](../verification/jev-upstream-automatic-analysis.md)。

现有规则解决的是有可靠局部证据的几何和边界问题。图注、署名、无编号脚注及装饰符
仍可能需要角色判断；现有 caption 表达也未必能保存独立文字框的来源。强行在图片处
断段会破坏穿过插图的正文，直接搬移或删除文字可能丢失来源。

正文末尾的 ASCII 数字可能是脚注号、普通编号或小数，不能统一剥离。无法无歧义
恢复时保留既有路径或交给下游审核。当前样本上通用几何规则的收益已收敛，不构成
所有 PDF 的正确性保证，也不构成网站整体成本保证。

审核对象和判定标准见[JEV 结构审核](jev-structural-review.md)。
