# LLM 验收原则与内容比较

PDF Craft 验收可交付的内容与结构，不要求模型逐字符遵守无关的表面格式。
程序可以无歧义处理的差异，不应导致额外模型请求；内部算法不能处理合法表达时，
应修复算法，不能不断新增协议或门禁要求模型迁就实现。

## 翻译与 fill 的职责

翻译 LLM 负责表达，提示只约束翻译、语气、风格和术语，不规定 XML/JSON、公式身份、
占位符或其他输出协议。艺术家回答不接受内容审查、拒绝或重译要求。

原始回答保留用于诊断。除共用非法字符清理外，允许一项可调整的优化：用 Markdown
解析器移除明确的格式、保留正文，生成工程纯文本视图；未识别语法保留，清理异常时
退回原文。fill 输入与全文比较使用同一份工程视图，整个修复 Loop 不改变它。

PCEX 的正文、脚注、独立图片/表格字段及原生 EPUB 共用一个有限 XML fill Loop。
来源 XML 提供稳定身份、结构和资源；fill 在一个回答中完成文字归属、格式与公式落位。
程序不生成译文公式占位符、身份表或范围协议，也不按位置或相似度推断对应。
不增加独立 JSON 分配、辅助模型或反向重译阶段。

## 全文与结构验收

全文验收只比较归一后的内容。

从最终候选按实际交付的阅读顺序提取内容，再与译文工程视图调用同一个共用字符串
比较函数。来源块身份决定实际写回位置，不能仅按回答树的排列宣布顺序正确。
比较视图不改写交付内容，也不改变来源偏移或 CFI。具体字符规则统一维护在
[翻译与 fill 的职责硬边界](../../references/translation-fill-boundary.md)，不在每个适配器
另设一套规则。CSS 保留模式、空白位于哪个 text/tail 字段，不构成额外的全文门禁。

结构验收保护真实交付要求：XML/格式可解析、必要身份和资源完整、引用有效、提交位置合法。
保留必要格式标签和身份；没有对应译文字元时允许格式槽为空，不能用原文、占位文字或
重复译文填满槽位。只读背景不能承载最终会被丢弃的译文。

PCEX/EPUB 适配器负责格式物化和内容提取。fill 原始回答先通过结构与全文门禁，物化在 Loop 成功后完成；工程转换错误不进入模型重试。公式的展示与隐藏
annotation 不得被重复计数，隐藏数据不能掩盖实际内容丢失。提交不能再改写已验收的
文字或偷换公式，脱离当前文档树的节点不能成为新的文档根。PCEX 持久化继续忠实保存
已采用内容，不套用交互层空白规则改写它。

真正的内容增删或结构损坏，应在同一个有限 fill Loop 中给出具体差异及位置，供模型修复。
失败不能部分采用或把回退原文标成译文；诊断日志保留到关联结果完整提交及直接内容回调成功。
日志生命周期见 [错误处理](ERROR_HANDLING.md#llm-修复与提交失败的现场记录)。

## friendly XML 与存储边界

所有模型 XML 输入和输出使用共用 friendly 编解码器。该编码器只处理表示与结构，
不授予额外语义验收权限；字面标签、实体拼写与真正结构必须区分。
详见 [LLM XML 编解码边界](../../references/llm-xml-boundary.md)。

`common/whitespace.py` 提供共用字符规则，`transformer/whitespace.py` 处理 friendly XML
及来源分段所需的保留上下文。HTML/CSS 的 normal、pre、pre-line 等规则仍可用于这些
运输和来源表示场景，但不用于重建 fill 字段空白归属或建立另一套内容比较门禁。
编码与分段继续保留必要混合内容边界；不能逐节点 trim 导致粘词。存储使用标准 XML
并保留已采用结果，不能把比较视图当成交付内容。
