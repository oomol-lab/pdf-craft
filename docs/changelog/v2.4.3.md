# PDF Craft v2.4.3

PDF Craft 2.4.3 fixes unbounded waits in optional LLM-assisted table-of-contents
analysis after OCR, which could prevent PDF-to-EPUB conversion from finishing.
LLM operations now have a default total time budget, with separate allowances
for resource cleanup.

## LLM timeouts and recovery

- Added keyword-only `LLM(total_timeout=360.0)`. Capacity waiting, streaming,
  transport retries and retry backoff share this budget. TOC JSON, schema and
  business-validation repair attempts also share one budget instead of each
  receiving a fresh timeout.
- `timeout` retains its HTTP connect/read/write/pool timeout meaning. A stream
  that keeps sending data can no longer extend the total operation indefinitely.
  `timeout=None` does not disable the total budget; use `total_timeout=None`
  explicitly to opt out. These settings apply to translation requests as well.
- Added `LLM(cleanup_timeout=5.0)`: stream close and client exit each receive half
  of this additional allowance. Slow cleanup no longer waits without a timeout;
  cancellation propagates without detaching cleanup tasks.
- TOC LLM failures, including total-budget exhaustion, fall back to statistical
  analysis so EPUB generation can continue. Caller cancellation propagates
  instead. EPUB output alone does not enable LLM requests.

The budgets rely on a responsive event loop and transports that cooperate with
cancellation. They do not impose a hard deadline on the entire PDF conversion.
Applications still own service watchdogs and failed-task state transitions.

See [#506](https://github.com/oomol-lab/pdf-craft/pull/506) for the initial deadline
fix; this release also includes the follow-up cleanup and configuration changes.

## Logging and verification

- Structured LLM events report requests, retries, success, timeout, failure,
  cancellation and cleanup timeout. Without `log_dir_path`, events propagate to
  the `pdf_craft.llm` parent logger; with a directory, they are written to request
  log files.
- Regression coverage includes streaming deadlines, combined transport and TOC
  repair budgets, slow cleanup, repeated cancellation, executor capacity reuse,
  fallback behavior, and synchronous/asynchronous EPUB conversion with and
  without a TOC LLM. Tests use simulated transports, without external API calls
  or OCR model downloads.
- Updated the English and Chinese API references for the timeout options and
  cancellation guarantees.
