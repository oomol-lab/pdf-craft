# PDF Craft v2.6.5

PDF Craft 2.6.5 adds translation-size previews and operation-scoped resource
reports, so applications can inspect source words before execution and observed
remote consumption after completion, failure or cancellation.

- New `pcex_words_count` and `epub_words_count` read-only queries share the actual
  translation pre-scan and source-word rules. Matching options produce the same
  total as translation's `STARTED.total_words`. Both Craft facades expose methods;
  the async facade keeps parsing outside the event loop.
- New `UsageCollector`, `UsageReport`, `Usage` and `RequestUsage` group observed
  requests and input/output/cache-hit input tokens by original provider object.
  Pass `usage=` to model-calling operations and inspect `usage.report()` without
  changing the operation's existing return type.
- Accepted and discarded consumption are separated as `effective` and `wasted`,
  including transport retries and business validation loops. Missing usage is not
  estimated. Provider prompt cache is distinguished from ordinary input; local
  cache hits do not create external consumption.
- Support LLM, JEV and OCR vendors. OCR counts recognition submissions rather than
  pages, authentication calls or polling. Existing `OCRTokensMetering` is retained.
- Classify translation and fill consumption for withdrawn PCEX metadata collections
  as wasted, including otherwise valid members of an incomplete `subjects` list.
  Independent accepted fields retain their effective consumption. Collections are
  translated separately from scalar fields so their usage can be settled accurately.
- Adopt `doc-page-extractor` 1.2.2 and clip second-pass vendor OCR boxes against the
  actual redaction masks. This prevents later-stage detections from extending into
  previously recognized regions, including oversized footer boxes that blocked PDF
  translation writeback. See [#545](https://github.com/oomol-lab/pdf-craft/pull/545).
- Read PCEX queue readiness and results from one SQLite snapshot, avoiding a race
  where online rendering or callbacks could read an unfinished result during scanning.
- Preserve sentence spaces between inline formula/formatting slots during XML
  fill validation and adoption. Correct fills no longer lose separators, and
  added separators cannot disappear before the canonical-text check.
  Keep required formula slots empty when the canonical translation assigns no
  characters to them; restore the original formulas after strict acceptance.
  Reconstruct formula-boundary padding from that canonical text instead of
  asking the fill model to reproduce it; other text and structural checks stay strict.
  Allocate merged canonical formulas through immutable math references rather
  than rebuilding delimiters for each source slot. Expand the exact canonical
  values before full text and ID validation, then restore original formulas.
- Preserve the full union of first-pass OCR redaction masks. A lower, narrower
  box no longer leaves the right side of a wider box visible to the footnote pass,
  preventing duplicate recognition caused by this leak. Add an opt-in paid
  citation.pdf regression with mask checks and English PDF writeback.
- Keep translated XML template text and inline word boundaries intact when
  encoding fill requests. Long values no longer gain formatting newlines, and
  mixed-content text/tails no longer lose their boundary spaces. Fill guidance
  keeps paragraph content compact; canonical text validation remains strict.
- Split extraction PAGE progress into first OCR, second-pass image preparation,
  and second OCR entry points. PAGE now uses stages 0–7 (`max_stage=7`);
  OCR-persisted/JEV/LLM/final stages move from 2/3/4/5 to 4/5/6/7.
  Consumers must update numeric stage labels; see the [stage table and migration](../en/TRANSLATION_PROGRESS.md).
  Retries, skipped stages and final publication/completion semantics are preserved.
  Custom async PDF handlers remain in stage 0 during pre-rendering; stage 1 starts
  only when the page enters OCR, keeping elapsed-time measurements accurate.
- See [usage and sizing](../en/USAGE.md) or [中文说明](../zh-CN/USAGE.md) for examples,
  the accounting boundaries, and limitations. PCEX v4 and the progress event structure are unchanged.

Resource reporting and task sizing: [#550](https://github.com/oomol-lab/pdf-craft/pull/550).
