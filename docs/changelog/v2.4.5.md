# PDF Craft v2.4.5

PDF Craft 2.4.5 lets hosts attach their own HTTP headers to provider requests,
so OCR and LLM calls made during one conversion can be correlated with the
host's request (for example by a gateway trace id).

## Request headers

- `DeepSeekOCRVendorConfig` and `DeepSeekOCR2VendorConfig` accept `headers`, a
  mapping of extra HTTP headers sent with every OCR request.
- `LLM` accepts a keyword-only `headers` mapping, sent with every Chat
  Completions request used for translation, metadata and TOC analysis.
- `Authorization` and `Content-Type` stay managed by pdf-craft; passing them
  raises `ValueError`. The headers are copied into an immutable mapping and are
  excluded from `repr`.

Existing configurations without `headers` behave exactly as in 2.4.4.
