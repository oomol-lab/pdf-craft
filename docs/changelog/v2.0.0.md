pdf-craft 2.0.0 reorganizes conversion around composable document-processing stages and adds translation capabilities for EPUB and PDF workflows.

## What's Changed

### Composable Conversion APIs

* Added public `PDFExtractor`, `DocumentPackage`, `MarkdownRenderer`, and `EpubRenderer` boundaries.
* Document packages preserve chapters, assets, TOC, optional cover art, and OCR pixel geometry needed by PDF replacement workflows.
* Existing `transform_markdown()` and `transform_epub()` entry points remain available as compatibility-oriented composition APIs.

### EPUB and PDF Translation

* Integrated the EPUB Translator XML processing stack for EPUB-to-EPUB translation, including EPUB 2/3 navigation, metadata, and spine handling.
* Added a replace-only PDF translation pipeline and patcher. PDF translation does not support append modes; images, tables, and formula assets are preserved rather than translated or redrawn.
* PDF patch output remains constrained by source bounding boxes, configured fonts, and available page space. Review translated PDFs manually before distribution.

### Smoke Matrix

* Added `python -m pdf_craft.smoke` for parameterized conversion smoke runs.
* Smoke runs preserve package/output/log/check artifacts under `analysing/smoke/<run-id>/` and distinguish passed, failed, skipped, and dry-run plans.
* Added real PDF and EPUB fixture inventories, including EPUB assets migrated from EPUB Translator.

## Migration Notes

The original convenience APIs remain supported. New integrations should prefer the explicit Extractor, DocumentPackage, Renderer, Pipeline, and Transformer boundaries so extraction, rendering, and translation can be combined independently.
