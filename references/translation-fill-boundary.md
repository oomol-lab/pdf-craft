# 翻译与 fill 的职责硬边界

**约束范围：** PCEX 与原生 EPUB 的正文、脚注、图注、表格、元信息和辅助字段；
包括提示、分组、XML fill、格式物化、验收、回填和失败处理。

## 架构原则

- 翻译 LLM 负责表达，fill LLM 负责工程落位。翻译提示只约束翻译、语气、风格和术语，
  不要求 XML/JSON、身份、占位符或其他输出协议；允许非强制建议未变公式保留 LaTeX。
  艺术家返回的内容不得被审查、拒绝或要求重译；网络故障属于调用层。
- 来源结构可以加工，程序不解释译文语义。来源 XML 可以准备稳定身份、资源和编辑骨架；
  文字归属、公式表达及重排由 fill 决定。禁止扫描译文后生成公式引用、占位符、范围表，
  禁止按位置、相似度或源公式语法猜测对应。
- 工程阶段只有一个有限 XML fill Loop。整组译文和来源骨架直接交给 fill，回答同时完成
  分配、格式和内容落位。禁止独立 JSON 分配、辅助模型、前后置修复、工程批外壳或反向重译。
- 全文验收只比较归一后的内容。
- 结构验收只保护真实交付要求：XML/格式可解析，来源身份和资源完整，引用有效，
  提交位置合法。每项门禁必须解释不检查会交付什么具体错误；内部算法处理不了合法表达时，
  修算法，不能把算法限制变成模型的新义务。不得把删除的门禁换名藏入结构检查。
- 验收最终将提交的结果。必要的格式物化在候选验收内完成，提交阶段不能再改写文字或
  偷换公式。目标身份必须定位到当前文档树；脱离树的节点不能成为新的文档根。
- 直接填充只用于没有分配歧义的极简单情况，例如唯一纯文本叶节点；仍经过同样验收。
  多容器归属和富文本重排交给 fill，不另造确定性填充引擎。
- 修复反馈报告可定位的文字增删、结构错误及 source/current 对照，不增加模型阶段或协议。
  修 bug 前区分候选真的损坏还是程序拒绝合法表达；后者修程序，不强迫模型迁就实现。
  新增门禁或译文预解释属于架构变更，不能作为局部修复擅自引入。

所有模型 XML 输入和输出遵守 [LLM XML 编解码边界](llm-xml-boundary.md)。
共用非法字符清理保持不变。friendly 包装只安全承载文字，不把字面标签变成结构。

## 工程视图与内容比较

原始艺术家回答保留用于诊断。一项可调整的优化是使用 CommonMark 解析器移除明确的
Markdown 格式、保留内容，得到工程纯文本视图。未识别语法保留；清理异常时使用原文，
不得因此拒绝或重译。这个优化不是硬约束，未来可以调整或移除。
fill 输入及全文比较使用同一份工程视图，整个 Loop 不改变它。

实现共用 `fill_text.comparison_text`：对完整字符串做 NFC，然后忽略共用空白策略中的
Unicode 空白、退格及明确列出的零宽填充。数字、大小写、标点、ZWJ/ZWNJ 和变体选择符
保留，不使用 NFKC、casefold 或模糊相似度。比较视图不改写交付内容，也不影响来源偏移/CFI。

候选按阅读顺序提取正文。格式适配器负责公式和隐藏数据的内容视图，不能重复计入 MathML
展示和 annotation；被丢弃的只读 context 不能承载译文。最终格式物化必须保持相同内容。
真正字符增删使用具体 diff 在同一 fill Loop 中修复。

## 聚合、采用与回归

跨章节连续使用既有 group 预算，尽量吃满 window，减少真实请求；不预载全书，不退回逐段
或逐 owner 请求。分组、有限并发、来源身份、CFI、coverage、进度与回调保留。
每个 group 一个自由翻译回答及一个有限 XML fill Loop；整组候选原子采用，其他 group 可并发。
失败不能采用部分内容或把原文标成译文；失败日志保留原始回答、工程视图与真实修复对话。

测试同时验证最终文字、结构、资源、根完整性和实际请求次数。包含 PCEX/EPUB 聚合、公式
重排/合并/数量变化、货币符号、Markdown、跨节点空白、Unicode 等价形式以及真实字词增删。
不能通过缩减预算、扩大 fallback、跳过内容或仅断言文件生成来制造成功。
