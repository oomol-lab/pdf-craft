# 翻译与 fill 的职责硬边界

**约束范围：** PCEX 与原生 EPUB 的正文、脚注、图注、表格、元信息和辅助字段；
包括提示、分组、XML fill、格式物化、验收、回填和失败处理。

## 架构原则

- 翻译 LLM 负责表达，fill LLM 负责工程落位。翻译提示只约束翻译、语气、风格和术语，
  不要求 XML/JSON、身份、占位符或其他输出协议；允许非强制建议未变公式保留 LaTeX。
  艺术家返回的内容不得被审查、拒绝或要求重译；网络故障属于调用层。
- 来源结构可以加工，程序不解释译文语义。来源 XML 可以准备稳定身份、资源和编辑骨架；
  文字归属、公式表达及重排由 fill 决定。禁止扫描译文后生成公式引用、占位符、范围表，
  禁止按位置、相似度或源公式语法猜测对应。
- 工程阶段只有一个有限 XML fill Loop。整组译文和来源骨架直接交给 fill，回答同时完成
  分配、格式和内容落位。禁止独立 JSON 分配、辅助模型、前后置修复、工程批外壳或反向重译。
- 全文验收只比较归一后的内容。来源非空不要求对应译文容器非空；完整艺术家译文已被采用时，
  保留空容器及其身份。同值文案在译文他处出现，不要求每个来源身份都非空，也不授权恢复来源重复次数。
  空字符串是采用结果，None 才表示没有可信译文，后续写回不能恢复来源文字。
- 结构验收只保护真实交付要求：XML/格式可解析，来源身份和资源完整，引用有效，
  提交位置合法。每项门禁必须解释不检查会交付什么具体错误；内部算法处理不了合法表达时，
  修算法，不能把算法限制变成模型的新义务。不得把删除的门禁换名藏入结构检查。
- fill Loop 只读验收模型原始 XML：friendly 解码、真实结构/身份检查，再提取内容做双侧归一比较。
  门禁前不得移动字段、恢复来源属性/文字、打平子树、复用公式或物化格式后再向模型追责。
  模型通过后才绑定来源资源/属性、执行公式复用与格式物化；这不是第二个模型阶段。
  后处理必须保全已接受内容，其错误是工程错误，不增加 fill 请求，不静默交付损坏产物。
  目标身份必须定位到当前文档树；脱离树的节点不能成为新的文档根。
- 直接填充只用于没有分配歧义的极简单情况，例如唯一纯文本叶节点；仍经过同样验收。
  多容器归属和富文本重排交给 fill，不另造确定性填充引擎。
- 修复反馈报告可定位的文字增删、结构错误及 source/current 对照，不增加模型阶段或协议。
  修 bug 前区分候选真的损坏还是程序拒绝合法表达；后者修程序，不强迫模型迁就实现。
  新增门禁或译文预解释属于架构变更，不能作为局部修复擅自引入。
- 来源锚点的身份、映射和边界必须在模型请求前自检。程序构造出不自洽的输入时直接报告
  工程错误，不能将其作为 fill 修复反馈消耗 Loop。跨章聚合的请求身份须与章内资产身份
  隔离；候选遗漏、增加、修改或错放输入要求的锚点仍在原有 fill Loop 内检查和修复。

所有模型 XML 输入和输出遵守 [LLM XML 编解码边界](llm-xml-boundary.md)。
共用非法字符清理保持不变。friendly 包装只安全承载文字，不把字面标签变成结构。

## 工程视图与内容比较

原始艺术家回答保留用于诊断。一项可调整的优化是使用 CommonMark 解析器移除明确的
Markdown 格式、保留内容，得到工程纯文本视图。未识别语法保留；清理异常时使用原文，
不得因此拒绝或重译。这个优化不是硬约束，未来可以调整或移除。
fill 输入及全文比较使用同一份工程视图，整个 Loop 不改变它。

全文验收先保留基础 NFC/约定空白等价；可选的 LaTeX 增强不能反过来否决已经相同的内容。
`fill_text.comparison_text` 仅构造共用字符串视图：顺序尝试有界的数学表达式子集，识别后
移除紧邻的数学定界符，允许只有左侧或右侧，不要求成对；两侧空白使用
`common.whitespace.is_whitespace`。相邻数学片段间的定界符也可忽略，使来源容器分段
不成为全文验收义务；实际数学内容、函数括号、分组和运算符保留。不扫描到
远处美元符来吞正文，不把通用 TeX 文档解析成功当成数学证据，不处理 TeX 注释。
可靠的数学内容可统一分组和符号写法；`$20`、`20$`、`$20$` 与 `20` 允许比较相等。
这是门禁的宽容度，不是产物改写，也不要求推断货币或公式的语义。无数学内容的孤立符号、未知构造和
失败保留原串。可选转换遇到不可靠状态整次回退，不保留半截转换结果，不生成身份或标记。

随后对完整字符串做 NFC，忽略共用策略中的 Unicode 空白、退格及明确零宽填充；数字、
大小写、标点、ZWJ/ZWNJ 和变体选择符保留。不使用 NFKC、casefold 或模糊相似度。
比较视图不改写艺术家回答、fill 输入或交付内容，也不影响来源偏移/CFI。

已由 fill 填写且对应到来源容器的公式，另用安全的平面字符串表示判断是否复用来源节点。
普通数字不受数学定界方式影响；已填写数学定界符且内容未变时可复用来源，
但不得给 fill 写下的裸文本补上来源定界符。来源4而译文40则保留40。
分式和脚本的分组必须保留，不能因有损打平而混淆不同数学内容；无法可靠转换时保留译文，
不拒绝、不重译，也不按位置或相似度猜公式身份。

候选按最终实际写回的阅读顺序提取正文。来源块 ID 绑定固定交付位置，回答 XML 的节点顺序不能冒充最终文档的调序。格式适配器负责公式和隐藏数据的内容视图，不能重复计入 MathML
展示和 annotation；隐藏 annotation 不能掩盖实际显示内容丢失。新建纯文字或混合内容的公式节点必须保留读者可见的原始字符，不可无条件按 LaTeX 解释。原始复杂 MathML 仅在已选来源公式内容未变时直接复用。最终格式物化必须保全已接受的内容。
真正字符增删使用具体 diff 在同一 fill Loop 中修复。

### Inline 的局部迁移

同一有限 fill group 内，真实来源树中共用同一祖父节点的兄弟 block，可以形成一个
`inline-scope`。其直接 inline 子节点可以在这些 block 之间平级移动和交换位置，
但不得跨祖父节点、跨层级或跨受保护的资源边界。移动外层 inline 时携带完整子树，
内部父子关系保持不变；独立公式的纯文本 payload 不是接收任意 inline 的容器。
请求聚合后的 `<xml>` 根不代表真实来源祖父节点，不得据此开放跨章节或跨文档迁移。
同一来源 block 被分片时，不将这些片段视作新的兄弟 block。

inline 的签名是 tag 与无序来源 attributes 的组合，不包含请求后来添加的标记。
纯流式调度标记不参与签名，格式适配器绑定来源资源所需的属性仍保留。
每个来源定义的交换域内，同 tag 只有一种签名时不携带 `signature` 或节点 ID，
候选至少保留一个该 tag，数量和合法位置可变。存在多种签名时，每种属性模板分配一个
`signature`；同签名共享标记，允许重复，每种签名至少出现一次。不允许新增来源不存在的
标签、签名，或给 inline 添加节点 ID。block 的唯一交付 ID 保持不变。
同签名的等价父包装共用下一层属性模板；子节点仍按父签名路径和层级检查，
不得移入不同父签名的子域、跨层级或越过真实来源的兄弟范围及资源边界。
验收只读解析模板对应关系，不提前恢复属性或来源内容；Loop 成功后才绑定来源属性，
保留模型选择的合法父节点、阅读顺序和全部文字。候选的 scope 标记不能扩大来源范围。
请求 signature 和 scope 不写入 PCEX/EPUB；来源本身的 attributes（包括原有 id）按模板恢复。

## 聚合、采用与回归

跨章节连续使用既有 group 预算，尽量吃满 window，减少真实请求；不预载全书，不退回逐段
或逐 owner 请求。分组、有限并发、来源身份、CFI、coverage、进度与回调保留。
每个 group 一个自由翻译回答及一个有限 XML fill Loop；整组候选原子采用，其他 group 可并发。
失败不能采用部分内容或把原文标成译文；失败日志保留原始回答、工程视图与真实修复对话。

测试同时验证最终文字、结构、资源、根完整性和实际请求次数。包含 PCEX/EPUB 聚合、公式
重排/合并/数量变化、货币符号、Markdown、跨节点空白、Unicode 等价形式以及真实字词增删。
不能通过缩减预算、扩大 fallback、跳过内容或仅断言文件生成来制造成功。

## Narrative 内容平等与重复反馈

PCEX 正文、脚注及独立公式共用阅读流与 group 预算。公式具有真实可编辑输出位置，
不保留来源内容豁免，不复制到相邻正文，不生成 formula_context 或要求模型返回空壳。
纯公式章节走相同流程。公式采用与缺失有明确 coverage；图片/表格资源锚点保持只读，
其展示文字仍属于独立 AnchoredContent，不混入 narrative。
来源格式适配可以保留公式表示，但不能在内容门禁前替换模型成果。行内公式内容未变时，
Loop 成功后可以复用来源表示，但保留工程师选择的定界方式；变化时保留译文。
不以汉字/拉丁字母比例猜测已经翻译完成并绕过艺术家。

内容差异以候选到译文的字符级 diff 展示，使用原有双侧归一化及编辑算法，
不修改验收条件。仅按精确匹配事实附加短提醒：新增片段已在候选别处存在、可靠的
非重叠出现次数不同、增删区域存在匹配。提醒只能提出可能性，不判定语义重复或
交换，不点名可疑字符串，不指定目标 XML 字段或命令模型采取某种修复动作。
重叠匹配不报告确定次数；混合的次数差异不选择一个片段冒充全部。数量提醒保留，
但不再笼统宣称必须补写或移动无效。不为句点增加专用忽略规则，不自动补齐/去重，
不反向审查艺术家，不增加模型阶段或预算。大型 diff 明确标注预览截断，完整译文始终提供。

## 修复输入与诊断

修复使用完整译文、一份实际失败回答及与它配对的反馈，并保留原始来源结构合同。
工作稿可以从本 Loop 的完整实际回答中择优选取；它始终是未采用的修复材料，不能
拼接历史片段、改写回答或以文字评分代替结构及全文验收。来源约束不得因输入精简
而放宽；不重复提供来源文字或已明确的结构，只是请求组织方式，不改变验收权限。
所有实际请求、回答和原始艺术家文本保留诊断，有限预算与请求阶段不变。

结构反馈保留真实身份和位置错误。内容反馈只读展示归一字符 diff 及有依据的
非指令性提醒，不再叠加自然语言的字段填充建议、局部替换配额或语义判断。
诊断是比较视图，不是可自动执行的 XML 补丁；格式物化仍在完整候选通过后进行。
